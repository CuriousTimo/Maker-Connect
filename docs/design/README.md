# Maker Connect v2: the target design

This folder describes the **v2 target design** of Maker Connect: what the hub, the agent and their
links are when hub core v2 (GitHub #13, steps #14-#20) is built. It describes the target only, not the
code as it stands (owner, 2026-11-19, [decision](decisions/20261119-design-doc-form.md)). Where the
plans leave something undecided, it is not filled in here: it is an open question in
[risks-and-open.md](risks-and-open.md).

Sources: [plans/hub-core-v2.md](../plans/hub-core-v2.md) (the design, "plan" below, `§` = its sections),
[plans/hub-core-v2-device-map.md](../plans/hub-core-v2-device-map.md) (each port on the contract),
[plans/hub-modules.md](../plans/hub-modules.md), [plans/hub-side.md](../plans/hub-side.md),
[plans/agent-engine.md](../plans/agent-engine.md), [plans/cameras.md](../plans/cameras.md), the
generated registries in [registries/](../registries/), the project rules in `CLAUDE.md` and the
owner's decisions in [decisions/](decisions/).

## How this folder is kept true

- The registry tables in `docs/registries/` are generated and fail a test on drift (plan §2.10).
- The API reference is `openapi.json`, generated by utoipa and failing a test on drift (plan §2.8);
  [api.md](api.md) is the map of it, not a second copy of every field.
- Every diagram is mermaid in a fenced `mermaid` block (GitHub renders it).
- A decision lands as a new file in [decisions/](decisions/), named `YYYYMMDD-slug.md`; a decision
  that changes an earlier one says which, and the earlier one gets `Status: superseded by …`.
