An update, step by step

Mockup: what About shows during and after an update.

  • Updating to hub-v2.0.1
    Database saved first (before-update dump, 15:50). The new build runs on trial; the page reconnects by itself.
    In progress
  • hub-v2.0.1 is running
    Confirmed at 15:52. The previous build is kept.
    Done
  • hub-v2.0.1 did not start, so the hub went back to hub-v2.0.0
    The database was restored from the dump of 15:50: changes made after the update started are lost.
    Rolled back
  • The update was not started
    The release's signature does not hold. Nothing changed.
    Refused

A new organisation is not made from this page: the API has no route for it yet.

Update the hub to hub-v2.0.1?

The hub saves its database first, then starts the new build on trial. If the new build does not confirm itself, the hub goes back to hub-v2.0.0 and restores the database: changes made in between are lost. Pages reconnect by themselves.

Move Printer-4 to Workshop South?

Its history stays in Workshop North. Its grants, requests and queue items in Workshop North are removed; its spool and camera are unlinked. In Workshop South its roles' defaults apply.
