The hub refuses the page's calls too (route guard); the navigation never offers it to a member.

  1. What are you adding?

  2. Point it here

    Put this file on the printer's USB stick as prusa_printer_settings.ini, then on the printer: load the settings and add it to Connect.

    [service::connect]
hostname = 192.168.1.20
port = 8080
tls = false
    The address must fit in the printer's hostname field: 20 bytes for firmware 6.3.0. hub.workshop-north.example is 27 bytes: use the IP address.

  3. Enter the code it shows

    POST /api/v1/devices/pair {code, name}
    That code is not waiting here. It may have expired: the printer or agent shows a new one; enter that one.

  4. Then: who may use it

    New machines need permission. Grant it in Space → Permissions.

The INI's three lines are today's (crates/hub/src/shell.js:89); the hub writes the exact lines for the printer's dialect (ui.md, Add machine). Machines kinds not in the v2 device contract (Klipper, virtual machines) are not offered.
