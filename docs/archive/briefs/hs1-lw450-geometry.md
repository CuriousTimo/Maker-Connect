Scope: the LabelWriter 450 only. The PnP (labelle) geometry is HS3, its own brief (separate stacks).

1. **Engine features.** A default feature (e.g. `devices`) holds every port and every device or
   heavy dependency (`serialport`, `libc`, `nusb`, `hidapi`, `maker-connect-grbl`, `png`,
   `fancy-regex`, `minijinja`, `serde_json`, `md-5`). Without it the engine builds only its core
   (`lib.rs`) and the 450's pure PPD code: `ports/dymo_cups/cups/{options,ppd,ppd_lw450,raster}.rs`.
   `page.rs` (PNG decode, halftoning) stays in `devices`; the W2 length rule `length_mm`
   (`page.rs:81`, ours) moves into the facade (item 3) and `page.rs` calls it there: moving code
   only, no change to any ported function. `png` stays a `devices` dependency. `cargo build -p maker-connect-engine
   --no-default-features` must work; the agent keeps the default.
2. **The PPD text of each size, generated.** `ppd_lw450.rs` is generated by
   `scripts/dymo-labelwriter-450-check.py gen` from `lw450.ppd`. Add each `PageSize` choice's
   translation text (the part after `/` up to `:`, e.g. `11353 Multi-Purpose`, `Banner`) to the
   generated data, with its line; `check` keeps failing if the file differs from what the PPD
   gives. Nothing on the wire changes (the text is never sent).
3. **The facade** `ports::geometry::lw450` (ours, thin): for every `PageSize` choice in PPD order:
   choice name (`w72h72`), its text, `PaperDimension`, `ImageableArea`, `cupsMediaType`, the raster
   in dots as `cups_raster_interpret_ppd` makes it for that choice (the same call the port's
   `page.rs` makes; no own formula), and the length in mm by the port's own W2 rule
   (`page.rs` `length_mm`; make it reachable, do not copy it). Tests (with `devices`): for
   every choice, a picture of the facade's dots and length is accepted by `page::make_page` (the
   port's own check); no hard-coded sizes.
4. **The hub uses it.** The hub depends on `maker-connect-engine` with `default-features = false`.
   The 450 profile's media list comes from the facade, not from the toml: one medium per `PageSize`
   choice, id = the choice name (unique; label numbers repeat, e.g. 99014, 99016), name = the PPD
   text plus the size in mm, width/length from the facade. Continuous sizes (`cupsMediaType 1`:
   `Banner`, `Continuous, Wide`) are listed as the PPD has them; whether the hub offers them is
   question Q2. The id is the hub's own key for its UI; a job still sends only `label_length_mm`
   (`page.rs:134` chooses the size by length and raster); HS1 adds no way to send the choice name,
   HS2 reconciles the two. The toml keeps only what is not geometry (brand, model, detect, dpi, head_dots).
   Test: the hub's dependency tree has no `serialport`, `nusb`, `hidapi` (`cargo tree -p
   maker-connect-hub -e normal`).
5. **Not in HS1:** drawing the page the port needs (HS2: `fit`/`media_dots`/`label.js`, raster size
   and orientation per choice); the PnP (HS3).
