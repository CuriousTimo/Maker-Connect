# Spoolman API: the hub's `/api/v1` against Spoolman

**The one reference:** Spoolman (github.com/Donkie/Spoolman, MIT) at commit `eccb05e`, version 0.27.1, in `reference/Spoolman`, run as it runs from source: uvicorn 0.54.0, FastAPI 0.162.0, Starlette 1.10.0, Pydantic 2.14.2, SQLAlchemy 2.0.54, aiosqlite 0.22.1, Alembic 1.20.1 (the versions of its own `uv.lock`, in `reference/.venv-spoolman`), CPython 3.12.13, on SQLite. Ours: `crates/hub/src/spoolman.rs`. The owner decided the hub is API- and data-compatible with Spoolman, not a copy: the API and the data are Spoolman's, the user interface is ours.

Proof: `scripts/spoolman-audit-check.py` starts real Spoolman on a fresh SQLite database on a free localhost port, sends it the request list below in order (`http.client`, no redirects followed, no gzip asked for) and writes status, headers and body of every answer to `crates/hub/src/spoolman/audit-fixture.json`. The Rust test `spoolman::audit` (`crates/hub/src/spoolman/audit.rs`) sends the same requests in the same order to the hub on a fresh store (signed in as the other hub tests are) and compares status, headers and body with the same normalisation. The measured differences are written in `crates/hub/src/spoolman/audit-differences.txt`; the test fails when they are not exactly that list, and this page is written from it (`scripts/spoolman-audit-check.py --doc`). The list is a snapshot of what the hub answers, written by the test from the hub's output, not judged by hand; it is only kept equal to the measurement.

The routes and the query parameters are read from Spoolman's own OpenAPI (`spoolman.api.v1.router.app.openapi()`): the script stops when a route or a query parameter has no request and no entry in its not-covered list. It covers 44 of Spoolman's 47 routes.

## Normalisation and what is not compared

- **now**: a string that parses as an ISO 8601 date-time (`T` or space between date and time) within 300 s of the time the request was made becomes `<now>`; any other date-time stays as it is (the requests use fixed dates in 2024).
- **paths**: in /info, `data_dir`, `logs_dir`, `backups_dir` become `<path>` (a temp dir); `latest_version` and `update_available` become `<volatile>` (Spoolman asks GitHub); in /backup, `path` becomes `<path>`.
- **headers**: in header values, `http://127.0.0.1:<port>` becomes `http://<host>` (the redirect's `location`).
- **json**: JSON bodies are compared as values and by key order: of the keys two objects both have, the order must be the same (Spoolman writes its models' field order; the hub keeps the order it inserts, `preserve_order`, chosen in the hub's own `Cargo.toml` so the order does not depend on what else is in the build).
- **text**: other bodies (CSV) are compared as text after the date-time rule.
- Header `date` is not compared: volatile: the time of the answer.
- Header `server` is not compared: set by the HTTP server (uvicorn), not by Spoolman's code.
- A vendor, filament or spool that the hub made for a `POST` that Spoolman refused is deleted through the hub's own API before the next request, so one difference does not shift the ids of the rest; the request is marked in the table. A location the hub made by name (a spool's `location`) is not deleted: it stays in the hub's list of places.
- Nothing is cut from the differences: every difference of every request is in the table. Equal differences in the items of one list are one line with `(xN)`, and the null fields are one line. Only the shown values are shortened (70 characters, 150 for a whole body; the comparison is on the full values), and the Spoolman column's message is shortened to 60.
- Requests that Spoolman refuses and that change something if accepted (`PATCH`, `PUT`) are sent last, to spare items (vendor 5, filament 5, spool 7).

## Ours, not differences

Headers the hub adds that Spoolman does not send (`OURS_HEADERS` in the test; not listed as differences):

- `access-control-expose-headers: x-total-count` on lists: the hub lets a browser page read the count; Spoolman sends it only when its CORS is configured.
- `/info` has `server: Maker Connect` beside Spoolman's fields (the hub's own name for what it is).

## Ours (owner)

Maker Connect's own additions. They are not in Spoolman, they leave Spoolman's fields as they are, and none of the requests below sets them (Spoolman would refuse the keys), so they are not compared:

- A filament's `extra` keys `kind` and `unit` (a label tape counts metres), `color_name`, `ink`, `media`, `width_mm` (a tape's width) and `minimum`.
- A spool's `extra` keys `loaded_in` (the machine it is loaded in) and `slot` (its slot in a dry box).
- Locations are places in the hub (with a code and a label); they go out as their names, and a new name makes a place.
- A spool's number is its code: spool 7 is the label `S-0007` (not in the API).
- The count-off: `use` and `measure` land on the amount of the spool as the hub's Materials page shows it.

## Not covered

- SpoolmanDB import and Spoolman's three `/external/*` routes (`GET /external/filament`, `GET /external/filament/search`, `GET /external/material`): the catalogue comes from the internet (9745 filaments); the hub's `spoolmandb.rs` is not compared either.
- The request bodies, the fields in them, the status codes asked for and the value variants (lengths, types, spellings) are chosen by hand; only the routes and the query parameters are derived from the OpenAPI. A case that is not in the list is not checked.
- WebSocket sequences (`/api/v1`, `/vendor`, `/filament`, `/spool` and `/{id}`, `/setting/{key}`, `/tag/scan/{reader}`): not run against Spoolman; the hub's own test checks one `updated` event of a spool.
- gzip: Spoolman compresses answers of 500 bytes or more for a client that sends `accept-encoding`; no request does.
- CORS and the trusted-origin and trusted-host guards (`SPOOLMAN_CORS_ORIGIN`, `SPOOLMAN_TRUSTED_ORIGINS`): no `Origin` or foreign `Host` is sent.
- Databases other than SQLite, `SPOOLMAN_BASE_PATH`, automatic backups, `/metrics`, the web client.
- Spoolman's own crash: `PATCH /spool/{id}` with `"extra": null` is a 500 in Spoolman at this commit; not asked.
- Request bodies larger than a few kilobytes, concurrent requests, a restart between requests.
- The hub's own endpoints that Spoolman does not have (`/export`, tag readers' live `GET /tag/scan`, `/api/v1/field/.../values` beyond one request): not asked of Spoolman, so there is nothing to compare.
